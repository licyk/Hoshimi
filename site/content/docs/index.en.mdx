Hoshimi is a model gateway written in Python. It puts free model stations (Cline, TRAE, ZCode, Qoder, MiniMax, Gemini, CodeBuddy, Kilo, OpenCode Zen and more), cloud services (Azure, Cloudflare, Vertex, Bedrock, NVIDIA NIM and more) and local or self-hosted OpenAI-compatible servers behind **one local server**: a client needs one base URL and one model catalogue to call any of those models through Chat Completions, Responses or Anthropic Messages, and a multilingual Web UI manages channels and accounts, browses models, chats and shows usage.

Install it, run `hoshimi serve` and open `http://127.0.0.1:10600`. The anonymous OpenCode Zen and Kilo entry points are on by default, with no account and no configuration file.

## What it does

| Feature | What it means | More |
| --- | --- | --- |
| One API | Chat Completions, Responses, Anthropic Messages and token counting under `/v1`, plus the model list | [Connecting clients](/docs/clients) |
| Channels and accounts | API keys, browser or device-code sign-in, automatic credential renewal, rotation across accounts, balances and daily check-in | [Channels](/docs/guide-channels), [Provider concepts](/docs/providers) |
| Model catalogue | Each model's abilities (reasoning, vision, tool calls), reasoning effort options and availability probes | [Models](/docs/guide-models), [Model behaviour](/docs/advanced-models) |
| Live usage | Calls in flight, token and cache breakdowns, first-token latency and generation speed, hour by hour for any day, kept in a local SQLite database | [Usage](/docs/guide-usage) |
| Playground | Chat with any model in the browser, optionally with built-in tools (read and edit files, run commands, search the web) that ask before they act | [Playground](/docs/guide-playground), [Playground tools](/docs/guide-agent) |
| Security | Separate keys for the management UI and the model API; allowed networks, host names and origins | [Security](/docs/config-security) |

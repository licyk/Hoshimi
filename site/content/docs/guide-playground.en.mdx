The **Playground** is a chat app built into the Web UI. It talks to models through the same gateway your clients use, so it is the quickest way to try a model, check an account, or see exactly what a request looks like. Chats are kept on the server, in the data folder, so they outlive the page and the process and come back from any browser.

This page covers chatting. Letting a model read files, run commands and search the web is covered in [Playground tools](/docs/guide-agent); the HTTP routes behind the page are in [Playground API](/docs/api-playground).

## Start a chat

<Steps>
<Step>

### Open the Playground

Choose **Playground** in the navigation. The page opens the chat you had open last (on any browser), or an empty one.

</Step>
<Step>

### Pick a model

The **Model** menu in the composer lists every model the server advertises; type to search when the list is long. The first model is picked when nothing is chosen yet. From the [Models](/docs/guide-models) page you can also open the Playground on one model, which starts a new chat with it.

</Step>
<Step>

### Ask

Type in the box and press <kbd>Enter</kbd>. The chat is created on the server with its first message, and the reply streams in.

</Step>
</Steps>

The chat list sits beside the chat on a wide window and slides in as a drawer on a narrow one; the button at the start of the header opens and closes it. The button at the end of the header starts what comes next: **New chat**, or, on a new chat no one has written in yet, **Temporary chat**.

| Key | Action |
| --- | --- |
| <kbd>Enter</kbd> | Send |
| <kbd>Shift</kbd>+<kbd>Enter</kbd> | New line |
| <kbd>Esc</kbd> | Stop the reply coming in |
| <kbd>↑</kbd> in an empty box | Edit your last question |
| <kbd>/</kbd> at the start of the box | Open the commands |
| <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>O</kbd> (<kbd>Cmd</kbd> on macOS) | New chat |

On a phone or a tablet, whose keyboard has no <kbd>Shift</kbd>+<kbd>Enter</kbd>, <kbd>Enter</kbd> starts a new line, and a message goes only when you tap **Send** (in the box, and when you edit a question). The hint under the box says so. While the command menu is open, <kbd>Enter</kbd> still runs the command that is highlighted.

The whole conversation scrolls as one. A tool's output, a compaction summary and a question being edited scroll on their own when they are long; once one reaches its top or its end, scrolling on in the same direction (the wheel, a trackpad or a swipe) moves the conversation instead of stopping there.

Pressing **Stop** (or <kbd>Esc</kbd>) ends the reply; what came so far is kept and the reply is marked **Stopped**.

A reply runs on the server, not in the page. Opening another chat, starting a new one, leaving the Playground or reloading the page does not stop it: it goes on in the background, and several chats can work at the same time. Open the chat again to watch it from where it is, with what it wrote so far; it can be stopped from there too. A reply that ends while no page shows it is kept, and its chat is named as usual.

## Commands

Type <kbd>/</kbd> at the start of the box to open the commands over the composer. Keep typing to narrow them (`/co` leaves **/compact** and **/status**, the matched letters in bold). <kbd>↑</kbd> and <kbd>↓</kbd> move, <kbd>Tab</kbd> completes the name, <kbd>Enter</kbd> runs the command and <kbd>Esc</kbd> closes the menu until you change what you typed. A command that chooses from a list opens the list once a space follows its name, and the words after it narrow the list: `/model gpt` then <kbd>Enter</kbd> picks the first match.

| Command | What it does |
| --- | --- |
| `/model` | Choose the model for this chat |
| `/effort` | Choose the reasoning effort, for a model that has levels |
| `/compact` *what to keep* | Compact the conversation now (see [Context and compaction](#context-and-compaction)); words after the name tell the summary what to pay attention to |
| `/status` | How much of the context window is used and left, the last request's and the whole conversation's tokens (cached ones among them), compactions, how long replies worked, and the tools |
| `/new` (or `/clear`) | Start a new chat |
| `/fork` *title* | Continue this conversation in a new chat, up to the message on screen; words after the name are its title |
| `/permissions` (or `/approval`) | Choose when tools ask before they run |

While a reply is running only `/status`, `/permissions` and `/new` run; the others say why they can't. A slash followed by something that is not a command, such as `/etc/hosts`, is sent as a message.

## Temporary chats

On a new, empty chat, the header button reads **Temporary chat**. A temporary chat works like any other but:

- it never appears in the chat list and is never named;
- it is deleted as soon as you leave it (open another chat or start a new one), and any left behind are deleted on the next start of the server;
- it has no chat menu and no **Branch in new chat**.

The box reads "Ask anything — this chat won’t be saved" while you are in one.

## The chat list

Chats are grouped by when they were last used: **Today**, **Yesterday**, **Previous 7 days**, **Previous 30 days** and **Older**. A chat branched from another carries a branch icon.

- **Search chats** filters the list by title as you type.
- Each chat has a menu (**Chat options**, the `…` button) with **Rename**, **Archive** and **Delete**. The same menu is in the header for the open chat.
- **Rename** sets your own title, which is never replaced by a generated one.
- **Archive** puts a chat away without deleting it. **Archived chats**, at the foot of the list, shows the archive; **Restore** brings a chat back, and so does sending a new message in it. **Back to chats** returns to the list. Archiving the open chat starts a new one.
- **Delete** asks first, then removes the chat, its messages and the attachments only it carried, for good. A reply working in it is stopped first, and any background commands its tools started are stopped.
- A chat whose reply is working now shows a spinner after its title (**Working…**), whether the page follows it or it works in the background; one whose tool call waits for your approval shows a shield (**Needs approval**) instead. Open it to answer.

### Titles

Until a model names it, a chat is titled by its first question (up to 80 characters). Once the first reply is complete, a model names the chat in at most six words, in the language you wrote in. Which model does that is the **Title model** setting (see Playground settings below); by default it is the chat's own model. If the model cannot be reached, the first question stays the title. A title you set with **Rename** is kept.

## Model and effort

The model and the effort are chosen in the composer and kept with the chat, so reopening it picks them up again. Both menus are locked while a reply is coming in.

- **Model**: any model the server advertises. Picking another model resets the effort to automatic.
- **Effort**: shown only for a model with reasoning levels. **Auto (server default)** sends no level and leaves it to the model and the provider; any other entry is sent as the request's `reasoning_effort`. See [Model behaviour](/docs/advanced-models) for how levels map to each provider.

## Attachments

Use **Add photos and files** (the `+` button), drop files anywhere on the chat, or paste them into the box. Each file uploads right away and shows in a tray above the text; remove one with its close button before sending. A message can go with attachments and no text.

| Kind | Accepted | How it is sent |
| --- | --- | --- |
| Images | PNG, JPEG, WebP, GIF | As an image. One larger than 2048 pixels on its longest side is scaled down in the browser (and re-encoded as WebP or JPEG); a smaller one under 1 MB, and any GIF that fits, goes as it is |
| Text files | Any `text/*` type, JSON, XML, YAML, TOML, SQL, shell scripts, and source files by extension (`.py`, `.ts`, `.vue`, `.rs`, `.go`, `.md`, `.csv`, `.log`, `.diff` and many more) | As text inside your message, under the file's name. Up to 2,000,000 characters can be attached; a model is sent the first 200,000 and told the rest was cut |
| PDF | Any PDF with a text layer | Its text is extracted in your browser page by page, then sent as a text file. A scanned PDF with no text is refused |

Anything else is refused with "send an image, a text file or a PDF". An attachment uploaded but never sent is deleted after a day. Attachments are stored once and shared by branches, so branching a chat does not copy them.

### Images and models that cannot read them

A model that reads images gets them as images. For one that does not (its catalogue entry says no vision), the Playground asks another model to describe each image, and sends the description in its place:

- The composer warns "This model can’t read images; another model will describe them." when you attach an image to such a model.
- While a description is being written the reply shows "Reading the image with *model*…".
- The reply carries a note saying which model described which image. The description is kept with the image, so it is asked for once, not on every turn.

Which model describes images is the **Image model** setting. **Automatic** takes the first model in the catalogue that reads images, skipping any the last availability probe found unavailable or region-blocked. **Off** never asks: the image is left out and the reply says so. You can also pick one model.

If a model listed as reading images is refused by its station because of the image, the reply is tried once more with descriptions, and a note says so.

## What a reply can show

Replies are Markdown, and the Playground renders more than text:

| In the reply | Shows as |
| --- | --- |
| `$…$` or `\(…\)` in a line; `$$…$$` or `\[…\]` on lines of their own | Typeset math (KaTeX). A wide formula scrolls sideways. A lone `$` stays a dollar sign, so "$5 and $10" is not math. TeX that cannot be read shows as code in the error colour |
| A ` ```mermaid ` block | The diagram, drawn in the interface's colours once the block is complete, with its kind (flowchart, sequence…) in the block's head. **Code** shows its source, **Diagram** the drawing again. It opens at its own size, or smaller to fit the column, but never below 60%, where its words would be too small to read; a frame shows at most 480 pixels of its height. A diagram larger than its frame fades out at the edges where there is more: drag it about, or scroll it sideways. Zoom it with <kbd>Ctrl</kbd> or <kbd>⌘</kbd> and the wheel, a pinch, or the head's **Zoom out** / **Zoom in** buttons; the percentage between them shows its size, and a click on it shows it at its actual size. **Fit to window** shows the whole diagram, and the arrows open it in the image viewer. A plain wheel still scrolls the chat. A diagram that cannot be drawn shows why, above its code |
| A ` ```svg ` block | The image. **Code** shows the source |
| A ` ```html ` block | Its code, with a **Preview** button that shows the page in a frame. The frame runs the page's scripts but cannot reach the network, this interface or its access key |
| `![description](address)` | The image. An address ending in `.mp4`, `.webm` or `.mov` shows a video player; `.mp3`, `.wav`, `.ogg` and similar an audio player |

Every code block, diagram and SVG has a toolbar for a head: an icon for what it holds (code, a command, a diff, a diagram, an image, a page), its language (**Python**, **Bash**…, or **Text** when the block names none), and its buttons, with **Copy code** last. HTML written directly in a reply (outside a code block) is shown as text.

**Media from other sites.** Loading an image tells the site that serves it you are reading, and the address can carry text from the conversation, so an image, video or audio file a reply points to on another site waits behind a button that names the site ("Load image from example.com"). Media written into the reply itself (a `data:` address) shows at once. To always load media, set **Images and video from other sites** to **Always load** in **Settings › Appearance**.

### The image viewer

Click any image in the chat (an attachment, an image in a reply, a diagram or an SVG) to open it in the viewer:

- **Zoom** with the mouse wheel, a pinch, a double click, or <kbd>+</kbd> and <kbd>-</kbd>; <kbd>0</kbd> or **Fit to window** goes back. Drag to look around while zoomed. Diagrams and SVG images stay sharp at every zoom.
- **Move** between all the images in the chat with the side buttons, <kbd>←</kbd> and <kbd>→</kbd>, or a swipe.
- **Download** saves the image; **Open in a new tab** opens it on its own (not offered for images written into the reply, which browsers do not open as pages).
- <kbd>Esc</kbd> or **Close** closes it.

## Reasoning

For a model that shows its reasoning, the reply starts with a folded line: **Thinking…** with the time so far while it reasons, then **Thought for** *time* once it answers. Click the line to read the reasoning; it stays as you left it. Models that do not return reasoning have no such line.

## Edit, retry and versions

A chat is a tree: editing a question or retrying a reply adds a new version beside the old one, and both stay readable.

- **Edit message** (on a question, or <kbd>↑</kbd> in an empty box for the last one) opens the question in place. Change the text, remove attachments, and press **Send** (or <kbd>Enter</kbd>; <kbd>Esc</kbd> cancels). The edit becomes a new version of that question, answered afresh; what followed the old version stays with it.
- **Try again** (on a reply) asks for another reply to the same question, with the model and effort now in the composer. Switch the model first to compare models on the same question. A failed reply also shows **Try again** next to its error.
- A turn with versions shows **Previous version**, *n* / *total* and **Next version**. Moving to another version also brings back the newest replies under it; they slide in from the side the arrow points to, while the messages above stay put. The version on screen is remembered with the chat.

Editing, retrying and switching versions are unavailable while a reply is coming in.

## Branch a chat

**Branch in new chat** (on a reply) copies the chat up to that reply into a new chat and opens it ("Opened in a new chat"). The new chat keeps the title, the model and effort, and the chat's approval mode; the original is untouched. Use it to take a conversation in two directions without switching versions back and forth.

## Copy as API request

Under **More actions** on a reply, **Copy as API request** copies a `curl` command that sends the same Chat Completions request through the gateway's public API:

```bash
curl http://127.0.0.1:10600/v1/chat/completions \
  -H "Authorization: Bearer $HOSHIMI_API_KEY" \
  -H "Content-Type: application/json" \
  -d @- <<'JSON'
{
  "model": "your-model",
  "messages": [
    {"role": "system", "content": "Answer briefly."},
    {"role": "user", "content": "Summarise this file.\n\n<file name=\"notes.txt\">\n...\n</file>"}
  ],
  "stream": true
}
JSON
```

The body is built on the server exactly as the reply was sent: the system prompt first, files inline, images as `data:` URLs (or as their descriptions, for a model that cannot read them), `reasoning_effort` when one was chosen, and the tool definitions with `tool_choice` when the chat has tools on. For a reply that used tools, it is the first round's request. Set `HOSHIMI_API_KEY` to your model API key, or drop the header when the server has none (see [Access and security](/docs/config-security)).

Use **Copy** on a message to copy its text, and **Copy code** on a code block to copy just the code.

## Context and compaction

Every model has a **context window**: how much of a conversation it can read at once. The ring beside the send button shows how much of it is left; press it, or type `/status`, for the details. The window is the one the model's station lists. When a station refuses a request as too long and names its real limit, that limit is used from then on.

When a conversation nears the window, it is **compacted**: a model writes a summary of the conversation so far (the goal, the decisions and why, what is done and still to do, the files involved, the next step), and from then on the model reads that summary, with your latest messages kept word for word, in place of everything before it. The conversation itself stays on screen. A line marks where it was compacted; press it to read the summary.

A conversation is compacted:

- **as a reply begins**, once the conversation has reached 85% of the window (`playground.compact_threshold`), or sooner when what is left could not hold a reply;
- **between a reply's rounds of tool calls**, so a long agent run keeps going;
- **when the model refuses a request as too long**: the conversation is compacted and the request sent again, and if that is still too long, once more with long tool outputs cut. This happens even with automatic compaction off;
- **when you type `/compact`**, optionally followed by what the summary should keep.

A compaction that fails leaves the conversation as it was. Editing a question from before a compaction, or branching from there, goes back to the whole conversation.

## How long a reply works

While a reply runs, a line at its foot says what it is doing (writing, running or reviewing a tool, compacting the context) and for how long, second by second. The clock stops while a tool call waits for your approval; time the review model takes counts. When the reply ends, **Worked for 1m 23s** (or **Stopped after**, **Failed after**) stays beside its actions; point at it to see when it started and ended.

## How a reply ended

| What you see | Meaning |
| --- | --- |
| **Stopped** | You stopped it, or the server stopped; the text that came is kept |
| **This reply failed.** and a reason | The model or the station returned an error; **Try again** retries |
| "The image … was described by …" | A model that cannot read images got a description |
| "The image … was left out: no model could read it." | No describing model was available, or **Image model** is **Off** |
| "… refused the image, so it was sent as a description." | The station refused the image; the reply was retried with descriptions |
| **Context compacted** above the reply | The conversation was compacted before it (see [Context and compaction](#context-and-compaction)) |
| "The conversation no longer fits in …'s context window, even compacted." | Even the compacted conversation is too long: start a new chat, or branch from an earlier message |

Notes about tools (a model that cannot call tools) are explained in [Playground tools](/docs/guide-agent).

## Playground settings

The Playground's own settings are in **Settings › General › Playground** (see [Settings](/docs/guide-settings)), and in `config.json` under `playground` (see [config.json](/docs/config)):

| Setting | Key | Default | What it does |
| --- | --- | --- | --- |
| **System prompt** | `playground.system_prompt` | empty | Sent first in every Playground chat, from its next message on. Empty sends none |
| **Title model** | `playground.title_model` | empty (**The chat’s own model**) | The model that names new chats after their first reply |
| **Image model** | `playground.vision_model` | `auto` (**Automatic**) | Describes images for models that cannot read them: `auto`, `off`, or a model id |
| **Compact long chats automatically** | `playground.auto_compact` | `true` | Compact a conversation as it nears the window. A request refused as too long is compacted either way |
| **Compact at** | `playground.compact_threshold` | `0.85` | The share of the window (0.5 to 0.95) at which a conversation is compacted |
| **Summary model** | `playground.compact_model` | empty (**The chat’s own model**) | The model that writes the summary |

```json
{
  "playground": {
    "system_prompt": "Answer briefly.",
    "title_model": "your-small-model",
    "vision_model": "auto",
    "auto_compact": true,
    "compact_threshold": 0.85,
    "compact_model": ""
  }
}
```

The tool settings (`playground.tools`, `workspace`, `approval`, `search_url`) are in [Playground tools](/docs/guide-agent).

## Where chats are kept

Chats, their messages and attachments live in `hoshimi.db` in the data folder (see [Data folder and paths](/docs/config-paths)), and are kept until you delete them. The chat open last is remembered there too, which is how the Playground comes back to it from any browser. A reply cut off by a server stop is kept as stopped.

Every model call the Playground makes is recorded in [Usage](/docs/guide-usage) like any other call, under its own origin: `playground` for replies, `playground-title` for titles, `playground-vision` for image descriptions, `playground-compact` for compaction summaries and `playground-review` for automatic reviews of tool calls.

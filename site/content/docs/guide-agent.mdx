开启工具后，Playground 的回复就成了一个智能体循环：模型可以使用内置工具；每一轮它先流式输出文字，它调用的工具依次运行（需要批准的先由审查模型或你批准），结果返回给模型，如此往复，直到某一轮不再调用工具为止。回复中的每次调用都显示为一张可以展开的卡片。

<Callout type="warn" title="工具会在本机上执行操作">

命令和文件编辑在运行 Hoshimi 的机器上执行，权限就是运行它的用户的权限，没有沙箱。所有工具默认开启，新对话从 **自动审查** 开始：每条命令、每次文件更改以及工作区外的访问在执行前都先由模型判断，有风险的会被拒绝。**先询问** 则全部交给你决定。下文的“安全”一节说明了每种模式会放行什么。

</Callout>

## 开启工具

<Steps>
<Step>

### 选择新对话默认开启的工具

打开 **设置 › 工具**，**新对话的工具** 中六个工具默认全部开启，关掉不需要的即可（见[设置](/docs/guide-settings)）。这里只是新对话的初始工具组合，不会强制任何对话使用工具。

如果你的配置文件从未设置过 `playground.tools` 或 `playground.approval`，现在会得到全部工具和 **自动审查**。配置中写明 `"tools": []` 的则一个工具都不开启。

</Step>
<Step>

### 为单个对话开启或关闭工具

输入框中的 **工具** 菜单（扳手图标）列出全部六个工具，每个都附有简短说明和一个开关；切换时菜单保持打开。按钮上显示已开启的数量，全部关闭时显示 **关闭**。对话可以开启设置中关闭的工具，也可以关闭设置中开启的工具。回复生成期间这个菜单不可更改。

</Step>
<Step>

### 选择支持工具调用的模型

只有支持工具调用的模型才会收到工具。目录中标记为不支持工具调用的模型会在没有工具的情况下作答，回复中注明“*模型* 不支持调用工具，因此在没有工具的情况下作答。”如果站点在回复开始前拒绝了工具，回复也会去掉工具再试一次，并给出同样的提示。

</Step>
</Steps>

对话只保存它与设置的差别（自己开启了哪些工具、关闭了哪些工具）。新对话会重新按设置开始。

## 六个工具

| 开关（设置与工具菜单中） | 模型看到的工具名 | 作用 | 何时先询问（完全访问下从不询问） |
| --- | --- | --- | --- |
| **读取文件** | `read` | 读取文本文件，或列出文件夹 | 仅当路径在工作区外 |
| **编辑文件** | `apply_patch` | 用补丁创建、修改、移动和删除文件 | **自动审查** 和 **先询问** 下总是询问；**仅在工作区外询问** 下只在涉及工作区外的文件时询问 |
| **运行命令** | `shell` | 运行一条命令并等待它结束 | 仅在 **自动审查** 和 **先询问** 下 |
| **后台命令** | `exec_command`、`write_stdin`、`kill_session` | 启动持续运行的命令，读取其输出、向其输入、停止它 | 启动命令或向其输入时，仅在 **自动审查** 和 **先询问** 下 |
| **网页搜索** | `web_search` | 用 DuckDuckGo 或你自己的 SearXNG 搜索 | 从不 |
| **读取网页** | `web_fetch` | 以 Markdown 形式读取公开网页 | 从不 |

在 **自动审查** 下，需要先询问的调用交给审查模型判断，只有它无法判断时才询问你（见下文的“自动审查”）。相对路径从工作区开始解析（见下文的“工作区”）。不论工具返回什么，发给模型的最多 32,000 个字符；更长的输出会截去中间部分，保留开头和结尾。

### 读取文件（`read`）

- 返回带行号的文本（`L12: …`）。默认从开头读取 2000 行，模型可以指定 `offset`（从 1 开始）和 `limit`（最多 10,000）分段读取。
- 超过 500 个字符的行会被截断；一次读取最多返回 60,000 个字符，并说明从哪里继续。
- 路径是文件夹时返回其内容列表：文件夹在前，最多 500 项。
- 二进制文件（开头部分含有 NUL 字节）会被拒绝。

### 编辑文件（`apply_patch`）

接受 Codex `apply_patch` 格式的补丁，在 Codex 中会用这个工具的模型在这里也会用：

```text
*** Begin Patch
*** Add File: hello.txt
+Hello world
*** Update File: src/app.py
*** Move to: src/main.py
@@ def greet():
-print("Hi")
+print("Hello, world!")
*** Delete File: obsolete.txt
*** End Patch
```

- 写入任何内容之前，会先对照现有文件算出整个补丁的结果：只要有一处无法应用，就不会修改任何文件。
- 文件必须是 UTF-8 文本。换行符保持原样（CRLF 文件仍是 CRLF），文件末尾总有换行。
- 结果列出新增（`A`）、修改（`M`）和删除（`D`）的文件。
- 补丁涉及工作区外的文件（或把文件移到工作区外）时，需要针对工作区外文件的批准：**更改工作区外的文件？**

### 运行命令（`shell`）

- 在模型指定的 shell 中运行命令，未指定时使用默认 shell（见下文的“选择 shell”），默认在工作区中运行，模型可以用 `workdir` 指定其他目录。
- 等待命令结束：默认 60 秒，最长 10 分钟。超时的命令连同它启动的所有进程一起被停止，并报告超时（退出码 -1）。
- 返回退出码、耗时和输出（包含标准错误）。命令没有输入（标准输入已关闭），分页器和颜色都已关闭（`PAGER=cat`、`NO_COLOR=1`、`TERM=dumb`、`GIT_TERMINAL_PROMPT=0`）。
- 对于持续运行或需要输入的命令，模型会被告知改用后台命令。

### 后台命令（`exec_command`、`write_stdin`、`kill_session`）

- `exec_command` 启动命令并等待一会儿（默认 10 秒，范围 0.25–30 秒）。如果命令已结束，返回退出码和输出；否则命令作为一个*会话*继续运行，并返回目前为止的输出和会话 ID。
- `write_stdin` 向会话输入内容（用 `\n` 表示回车），并返回新的输出，写入后默认等待 0.25 秒；不输入任何内容时只等待新输出（默认 5 秒，最长 2 分钟）。它会说明命令是否仍在运行，或给出退出码。
- `kill_session` 停止会话及其启动的所有进程，并返回最后的输出。
- 每个会话最多保留 1,000,000 个字符的未读输出（超出部分丢弃中间）；颜色控制码会被去掉。
- 整个服务端同时最多运行 16 个后台命令。会话属于启动它的对话，该对话被删除或服务停止时会随之停止。

`exec_command` 和 `shell` 一样会先询问。`write_stdin` 输入内容时也会询问（**运行此命令？**），因为向 shell 输入就是在运行命令；只读取输出时从不询问。`kill_session` 从不询问。

### 选择 shell

`shell` 和 `exec_command` 有一个可选参数 `shell`：`bash`、`zsh`、`sh`、`powershell`（优先使用 PowerShell 7 的 `pwsh`，其次是 Windows PowerShell；也接受 `pwsh` 这个名称）或 `cmd`，可以写名称，也可以写路径（如 `/usr/bin/zsh`）。未知或未安装的 shell 会报错，模型会读到错误和本机已安装的 shell 列表。

| Shell | 命令的运行方式 |
| --- | --- |
| bash、zsh、sh | `<shell> -c <命令>`，从不作为登录 shell |
| PowerShell | `-NoLogo -NoProfile -NonInteractive -Command <命令>` |
| cmd | `/d /s /c <命令>` |

调用未指定 shell 时，命令在 **设置 › 工具 › 工具如何运行 › Shell**（`playground.shell`）中选择的 shell 中运行。默认的 **自动** 使用 bash，没有 bash 时用 `sh`；Windows 上使用 PowerShell，没有时用 cmd。该选项会显示当前实际使用的 shell（“当前为 bash”）。菜单只列出本机已安装的 shell；所选 shell 未安装时按自动处理。工具说明会告诉模型默认的 shell 和已安装的 shell，命令的结果也会注明它在哪个 shell 中运行。

### 网页搜索（`web_search`）

- 使用 DuckDuckGo 的轻量页面（无需密钥），或使用 **SearXNG 地址**（`playground.search_url`）中设置的 SearXNG 实例，该实例需要开启 JSON 格式。
- 默认返回 8 条结果（最多 20 条），每条包括标题、地址和摘要。
- DuckDuckGo 会限制请求频率；不再响应时稍等片刻，或改用 SearXNG。

### 读取网页（`web_fetch`）

- 读取公开的 `http://` 或 `https://` 地址（未写协议时补上 `https://`），返回最终地址、标题和内容。HTML 会转换为 Markdown，保留标题、段落、链接、列表、代码和表格，去掉脚本、样式、导航和表单，并优先取页面的主要内容。
- 只读取文本（HTML、纯文本、JSON、XML、RSS 等）；最多下载 5 MB，返回 60,000 个字符。
- 本地和私有地址会被拒绝：`localhost`、以 `.localhost`、`.local` 或 `.internal` 结尾的名称，以及解析到回环、私有、链路本地、保留或多播地址的任何名称。每次重定向（最多 5 次）都会重新检查。包含用户名或密码的地址也会被拒绝。这样模型就读不到保存着你账号凭据的网关本身，也读不到你网络中的其他设备。

两个网页工具都按网关的网络设置（包括代理）访问外网（见[网络](/docs/config-network)）。

## 工具何时先询问

审批模式决定哪些调用需要批准，以及由谁批准：审查模型或你。新对话按 **设置 › 工具 › 工具如何运行 › 工具何时先询问** 开始；每个对话可以单独选择。

| 模式（`playground.approval`） | 简称 | 在以下操作前询问 |
| --- | --- | --- |
| **自动审查**（`review`，默认） | **自动审查** | **先询问** 下会询问的调用交给审查模型允许或拒绝；只有它无法判断时才询问你 |
| **先询问**（`ask`） | **询问** | 每条命令（`shell`、`exec_command`，以及输入内容的 `write_stdin`）、每次文件更改，以及读取工作区外的任何内容 |
| **仅在工作区外询问**（`workspace`） | **工作区** | 只在读取或更改工作区外的文件时询问；工作区内的命令和更改直接运行 |
| **完全访问**（`full`） | **完全访问** | 从不询问，工具按模型的调用执行一切操作 |

搜索和读取网页从不询问，读取工作区内的文件也不询问。配置文件和 API 仍接受 `workspace` 的旧名称 `auto`；以它保存的对话会改为 `workspace`。

### 输入框中的盾牌菜单

对话至少开启了一个工具时，输入框中 **工具** 旁会出现一个盾牌。它显示该对话的模式（**自动审查** 为带对勾的盾牌，**询问** 为带人像的盾牌，**工作区** 为半个盾牌，**完全访问** 为红色的划掉的盾牌），点开 **工具何时先询问** 可以只为这个对话更改模式。回复进行中也可以更改：新模式从下一次工具调用起生效。新对话会重新按设置开始。在手机上，盾牌只显示图标。

## 自动审查

在 **自动审查** 下，**先询问** 中会询问的调用改为交给模型判断，而不是询问你：每条 `shell` 和 `exec_command`、输入内容的 `write_stdin`、每次 `apply_patch`，以及工作区外的 `read`。审查模型在 **设置 › 工具 › 工具如何运行 › 审查模型**（`playground.review_model`）中设置；默认留空，即 **对话自身使用的模型**。建议选择快速而谨慎的模型。

审查模型会收到：

- 一份固定的审查规则，改编自 OpenAI Codex 的自动审查（“guardian”）。规则告诉它这里没有沙箱。
- 到目前为止的对话记录。只有你的消息算作可信；助手的文字、它的工具调用及其输出都不可信，所以文件或网页中埋下的指令无法授权任何操作。
- 以 JSON 表示的待执行调用：工具、参数、它需要什么批准、是否涉及工作区外、工作区，以及命令所用的 shell。

审查模型自己不能运行任何东西。它的回答包括风险等级（low、medium、high 或 critical）、你授权这次调用的明确程度（unknown、low、medium 或 high）、结论和一句理由：

| 风险 | 结论 |
| --- | --- |
| 低、中 | 允许 |
| 高 | 只有在你明确要求（授权至少为 medium）且范围很窄时才允许 |
| 严重 | 拒绝 |

高风险和严重风险的操作包括：删除无法恢复的数据、强制推送共享分支、把密钥或隐私数据发到不可信的地方、从不寻常的位置读取凭据、长期削弱安全设置等。

- **允许**：调用照常运行。展开卡片会显示“*模型* 已允许”，并附上风险和理由（如有）。
- **拒绝**：卡片显示 **审查已拒绝**，展开后显示“*模型* 已拒绝 · 高风险 — *理由*”。模型会被告知理由，并被告知不要绕过它：不能换个办法、间接执行或改用其他工具达到同样目的；只有找到明显更安全的替代做法，或你在了解风险后明确批准，才能继续；否则它会停下来询问你。
- **无法判断**：一次审查最多 90 秒。如果审查失败（站点出错、太慢，或回答不是一个结论），调用不会被拒绝，而是像 **先询问** 一样停在 **等待批准** 等你决定，卡片上注明“自动审查无法判断，因此询问你 — *原因*”。

审查进行中，卡片显示 **审查中…**，回复底部一行显示 **正在审查 *工具*…**。审查时间计入回复自己的用时；等你批准的时间则不计入“用时”。

如果审查模型连续拒绝 3 次调用，或在一条回复中共拒绝 10 次，回复会被停止：这一轮剩下的调用标记为 **已停止**，回复以“自动审查拒绝了此回复的 *n* 次调用，因此已停止。请说明如何继续，或换一种批准模式。”结束。

你之前在对话中给出的 **始终允许** 仍然有效：它涵盖的调用直接运行，不询问任何人，也不经过审查模型。

## 批准调用

需要询问你的调用会停在 **等待批准** 状态并自动展开，显示它将要做什么（命令，或标出增删行的补丁）以及一个问题：

| 问题 | 对应的调用 |
| --- | --- |
| **运行此命令？** | `shell`、`exec_command`，或向会话输入内容的 `write_stdin` |
| **应用这些更改？** | 工作区内的补丁 |
| **更改工作区外的文件？** | 涉及工作区外文件的补丁 |
| **读取工作区外的此文件？** | 读取工作区外的 `read` |

可以选择：

- **允许**：运行这一次调用。
- **始终允许**：运行这次调用，并且在此对话中运行同类调用时不再询问。“同类”指同一个工具开关，且工作区内和工作区外分开计算：始终允许工作区内的编辑，并不允许工作区外的编辑。这一许可持续到服务重启，删除对话时也会被清除。
- **拒绝**：跳过这次调用。模型会被告知你拒绝了它，除非你要求否则不要再试；卡片显示 **已拒绝**。

调用最多等待 10 分钟，没有答复视为拒绝。停止回复会同时取消正在等待的调用。

## 工具卡片

每次调用在回复中占一行：图标、动词和作用对象（**读取** `路径`、**编辑** `文件`、**运行** `命令`、**启动** `命令`、**查看** 或 **输入到** *会话 n*、**停止** *会话 n*、**搜索**“关键词”、**打开** *地址*），然后是状态：

| 状态 | 含义 |
| --- | --- |
| **准备中…** | 模型还在写这次调用 |
| **审查中…** | 审查模型正在判断它 |
| **等待批准** | 等你答复 |
| 转圈图标和计时 | 正在运行 |
| 对勾和耗时 | 已完成 |
| **退出码** *n* 或 **失败** | 命令以错误退出，或工具执行失败；模型会读到原因 |
| **已拒绝** | 你拒绝了它 |
| **审查已拒绝** | 审查模型拒绝了它；模型会读到原因 |
| **已停止** | 回复在它完成前被停止 |

点击卡片可以展开：发送的命令、补丁或参数，以及返回的结果。两轮之间，回复处显示 **处理中…**。

## 在回复进行中补充说明

开启了工具的回复运行期间，你可以在不停止它的情况下补充内容。输入框提示“补充说明，模型会在下一步读到…”；输入后按 <kbd>Enter</kbd>（或点按钮，此时为 **发送给正在进行的回复**）。

- 你的消息以淡色显示在回复下方，并标注 **当前步骤完成后读取**。模型在下一轮开始时（当前调用完成后）读取它，之后它会出现在回复中被读取的位置。
- 在模型刚好收尾时发送的消息，会让回复再继续一轮来回应它。
- 如果回复已经结束，消息会放回输入框（“回复已经结束，你的消息已放回输入框。”），你可以把它作为新消息发送。如果回复在读取之前被停止或失败，文字同样会回到输入框。
- 输入框为空时，按钮仍是 **停止**；<kbd>Esc</kbd> 总是停止回复。

## 输入框上方的后台命令

对话的工具通过 `exec_command` 启动、仍在运行的命令列在输入框上方（**后台命令**）：显示命令、**运行中** 和一个停止按钮（**停止** *命令*），它会停止该命令及其启动的所有进程。这些命令在两次回复之间持续运行，直到模型或你停止它们、对话被删除或服务停止。

## 工作区

工作区是工具的起点：相对路径在这里解析，`shell` 和后台命令默认在这里运行（除非模型指定了其他目录）。它在 **设置 › 工具 › 工具如何运行 › 工作区** 中设置（`playground.workspace`，支持 `~`）；留空时使用数据目录中的 `workspace` 文件夹（见[数据目录与路径](/docs/config-paths)）。开启工具的回复第一次运行时自动创建。

工作区是审批模式的分界线：在 **先询问** 和 **仅在工作区外询问** 下，读取或更改工作区外的文件都会询问；在 **自动审查** 下则交给审查模型判断。但它不是命令的边界：命令可以 `cd` 到任何地方，操作运行 Hoshimi 的用户能操作的一切。

## 停止

一条回复需要多少轮工具调用就进行多少轮，没有上限；模型不再调用工具、直接作答时回复结束。**停止**（或 <kbd>Esc</kbd>）立即结束回复。正在运行的 `shell` 命令会连同其启动的进程一起停止；等待批准或正在审查的调用被取消；尚未运行的调用标记为 **已停止**。回复到此为止说过和做过的内容都会保留。后台命令会继续运行：请在输入框上方停止它们。

## 安全

没有沙箱。工具以运行 Hoshimi 的用户身份在那台机器上运行，能访问它的文件、凭据和网络。

- 只有在 **先询问** 模式下，你才能在每条命令、每次文件更改发生前看到它。批准前请逐一看清楚。
- **自动审查** 是模型的判断。它可能两头出错，放行不该放行的、拒绝没有问题的，也可能被欺骗。它是一道防护，不是沙箱。
- **仅在工作区外询问** 会不经询问运行任何命令。命令并不局限于工作区，所以在这个模式下，模型可以修改或删除该用户能访问的任何文件，也可以访问你的网络。只在你信任模型和任务时使用。
- **完全访问** 不经询问运行所有调用，包括对工作区外文件的编辑。
- **始终允许** 会在此对话的剩余时间里（直到服务重启）不再询问，在 **自动审查** 下也不再经过审查模型。需要每次检查的操作，请选择 **允许**。
- `web_fetch` 会拒绝本地和私有地址，但 `shell` 和后台命令不会：命令可以访问这台机器能访问的一切，包括网关自己的 API。
- 模型读到的内容（网页、文件、命令输出）可能包含试图操纵它的指令。工具会读取不可信内容时，请使用 **先询问**。
- 如果其他机器可以访问这个服务，任何能登录网页界面的人都能使用这些工具。请设置访问密钥并限制可连接的来源（见[访问与安全](/docs/config-security)）。

## 设置参考

| 设置（**设置 › 工具**） | 配置项 | 默认值 |
| --- | --- | --- |
| **新对话的工具** | `playground.tools`：`read`、`apply_patch`、`shell`、`terminal`、`web_search`、`web_fetch` 中的任意几个 | 全部六个（`[]` 表示全部关闭） |
| **工具何时先询问** | `playground.approval`：`review`、`ask`、`workspace`（旧名称为 `auto`）或 `full` | `review` |
| **审查模型** | `playground.review_model` | 空：对话自身使用的模型 |
| **Shell** | `playground.shell`：`auto`、`bash`、`zsh`、`sh`、`powershell` 或 `cmd` | `auto` |
| **工作区** | `playground.workspace` | 空：数据目录中的 `workspace` |
| **SearXNG 地址** | `playground.search_url`（`http(s)` 地址） | 空：DuckDuckGo |

`terminal` 是三个后台命令工具共用的开关。

```json
{
  "playground": {
    "tools": ["read", "apply_patch", "shell", "web_search", "web_fetch"],
    "approval": "review",
    "review_model": "",
    "shell": "auto",
    "workspace": "~/hoshimi-work",
    "search_url": ""
  }
}
```

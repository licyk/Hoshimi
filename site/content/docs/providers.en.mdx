Hoshimi treats each upstream service as a **channel** (called a provider in code and configuration, and named by an ID such as `cline`, `opencode` or `agg`). A channel holds one or more **accounts**, and the accounts of one channel form its **account pool**: requests rotate through it. This page explains those ideas and the common ways to add an account; the other pages in this section cover each kind of channel.

## Kinds of channel

| Kind | Example channel IDs | Where accounts come from | See |
| --- | --- | --- | --- |
| Anonymous lanes | `opencode`, `kilo` | None needed; on by default | [Anonymous lanes](/docs/providers-anonymous) |
| Free stations and subscription logins | `cline`, `gemini`, `zcode`, `minimax`, `trae`, `qoder`, `qodercn`, `buddy`, `workbuddy`, `codearts`, `loomy`, `raccoon`, `lobsterai`, `codex`, `eac`, `zhipu` | Browser or device-code sign-in (`zhipu` uses an API key) | [Free stations](/docs/providers-stations) |
| Generic compatible lane | `agg` | Your own base URL or one of 22 presets, plus an API key | [The agg aggregator](/docs/providers-agg) |
| Cloud platforms and special protocols | `azure`, `cloudflare-workers-ai`, `cloudflare-ai-gateway`, `google`, `google-vertex`, `amazon-bedrock`, `radius`, `typesafe` | Platform keys, Google or AWS credentials | [Cloud platforms](/docs/providers-cloud) |
| NVIDIA NIM | `nvidia` | API key | [NVIDIA NIM](/docs/providers-nvidia) |
| Conventional API services and local backends | `openai`, `anthropic`, `openrouter`, `deepseek`, `groq`, …; `lmstudio`, `ollama`, `llamacpp` | API key, some with sign-in; key optional for local servers | [Local and compatible endpoints](/docs/providers-local) |

The [provider inventory](/docs/providers-inventory) maps every channel to its sources. An inventory row records that an entry point exists, not that the upstream currently answers.

## Similar names, different IDs

Different products, plans and protocols from the same company use different channel IDs, and their credentials are not interchangeable:

- `minimax` is a MiniMax Agent login; `minimax-api`, `minimax-cn` and `minimax-chat` are three key-billed public APIs.
- `gemini` is Gemini Code Assist (Google account sign-in); `google` is the Gemini Developer API (API key); `google-vertex` is Vertex AI.
- `amazon-bedrock` (ConverseStream) and `bedrock-mantle` (an OpenAI-compatible endpoint) are configured separately.
- `zhipu` is bigmodel.cn's general API; `zai`, `zai-coding-cn` and `zai-api` are Z.AI's coding plans and international API; `zcode` is the ZCode client's sign-in lane.
- `cline` is Cline's free sign-in lane; `cline-pass` is a ClinePass subscription key.
- `typesafe` provides classification, not chat models.

## Adding an account

All three ways write the same file: `config.json` in the data folder (`hoshimi config path` prints its location). The Web UI and `hoshimi login` apply immediately; if you edit the file by hand, restart the server.

<Tabs items={["Web UI", "Command line", "config.json"]}>
<Tab value="Web UI">

1. Open the **Channels** page and pick a channel. Channels without accounts are under the **Not set up** filter.
2. For a channel that supports sign-in, click **Sign in** and finish in the browser as the dialog says. For the others, click **Add account**, choose an **Authentication method**, fill in the form and click **Save account**.
3. The account appears under **Accounts**. Adding an account also switches a disabled channel back on.

</Tab>
<Tab value="Command line">

```bash
hoshimi login                 # list the channels that offer an interactive login
hoshimi login cline           # sign in in the browser; the account lands in config.json
hoshimi login cline --no-open # print the link without opening a browser
hoshimi stations              # list the station presets agg accepts
hoshimi providers             # show the channels and their account counts
```

</Tab>
<Tab value="config.json">

```json
{
  "providers": {
    "nvidia": {
      "enabled": true,
      "accounts": [
        {"id": "nvidia-1", "api_key": "<NVIDIA API key>"}
      ],
      "options": {}
    }
  }
}
```

</Tab>
</Tabs>

Signing in again as the same station identity updates the existing account instead of adding a second one. To delete an account, use **Forget** in its menu: the credential is removed from `config.json` and from the running pool.

<Callout type="warn" title="config.json is the credential store">

Account tokens and keys are stored in plain text in `config.json`. Do not commit or share a file with real credentials in it; replace them with placeholders before sharing an example.

</Callout>

### Keys for each channel

| Key | Meaning |
| --- | --- |
| `providers.<id>.enabled` | `false` switches the channel off entirely (this is also how the anonymous lanes are turned off). On when omitted. |
| `providers.<id>.accounts` | The list of accounts; each is an object whose fields depend on the channel. |
| `providers.<id>.accounts[].id` | The account's name, used in the UI, usage records and logs. When omitted the gateway names it (a login produces names like `cline-1a2b3c`; an unnamed entry is named by position, like `<id>-0`). |
| `providers.<id>.options` | Channel-level options, such as TRAE's `channel`, agg's capability declarations or a local server's `models`. |
| `providers.<id>.options.network` | The channel's own network route; inherits the global setting by default. See [Network and proxies](/docs/config-network). |

## Choosing a model: routing rules

Clients name the model in the request's `model` field:

- `channel/model` (for example `opencode/big-pickle` or `nvidia/<model-id>`) goes straight to that channel.
- A bare model ID goes to the first channel that lists it, in this fixed order: `cline`, `opencode`, `kilo`, `gemini`, `zcode`, `minimax`, `trae`, `qoder`, `qodercn`, `buddy`, `workbuddy`, `codearts`, `loomy`, `raccoon`, `lobsterai`, `eac`, `agg`, `zhipu`, `nvidia`, then every other channel.
- When only one channel is enabled, an unknown ID is passed to it unchanged.

`GET /v1/models` lists each ID once; `owned_by` is the channel that wins by the order above. When the model ID itself contains a `/` (Kilo's `openrouter/free`, for example), add the channel prefix, `kilo/openrouter/free`, so the first segment is not read as a channel name. Client setup is in [Connecting clients](/docs/clients).

## Account pools and rotation

A channel's accounts are used in the order they are configured. When a request meets an account-level failure, the gateway retries on the next account, asking at most `server.max_account_retries` accounts per request (default 3):

- Quota exhausted or rate limited: the account is held out of rotation for the reset time the upstream gave, or one hour if it gave none.
- Credentials refused: the gateway tries to renew them, then moves to another account. When the refresh token itself is refused, the account is marked **Needs login** and stays out of rotation until you sign in again.
- Once any content has gone to the client, a request is never replayed automatically.

The full rules are in [Model behaviour](/docs/advanced-models).

## Renewal and check-in

The tokens of many sign-in stations expire. With **Credential renewal** on (`server.auto_refresh`, on by default) the gateway checks every 30 minutes and renews accounts that expire within the hour or record no expiry. With **Daily check-in** on (`server.auto_checkin`, on by default) it claims each supporting station's free credits once a day, by the calendar day in UTC+8. Which stations support renewal, check-in and balance queries is listed in [Free stations](/docs/providers-stations).

## How to choose

- Start with the [anonymous lanes](/docs/providers-anonymous), which are on by default and need no account.
- For a larger free allowance, sign into [free stations](/docs/providers-stations); several accounts give the rotation more room.
- If you already have a key for an OpenAI-compatible service, use its native channel when it has one (see [Local and compatible endpoints](/docs/providers-local)), otherwise [agg](/docs/providers-agg).
- Use the matching [cloud platform](/docs/providers-cloud) channel for enterprise cloud accounts, and LM Studio, Ollama or llama.cpp for models on your own machine.
